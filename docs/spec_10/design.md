# Design

## Existing architecture and read-side hazards
`nifty_lab/execution/ledger/store.py`: ExecutionLedger.__post_init__ creates/migrates tables and initial funding. portfolio_context() / _portfolio_context_conn() can update peak_equity. Do NOT instantiate ExecutionLedger or call get_ledger()/portfolio_context() from the results page or its loader. Do not change their execution behavior in this slice.

Use the actual known Paper path derived from the existing `_ledger_path(ExecutionMode.PAPER)` convention: PROJECT_ROOT/data/paper_execution.db, with no arbitrary user path picker and no Live/Sandbox selector. Open existing database only via correctly encoded SQLite URI mode=ro, PRAGMA query_only=ON; read a single consistent transaction and close it. Do not use immutable=1 on an actively writable database or copy a live .db without its WAL. If WAL/environment prevents safe read-only access, show unavailable; no fallback to writeable connection. No DB initialization, migration, peak update, mark fallback writes or funding insertion. Refresh may re-read this local snapshot only.

Read tables/required columns and metadata with schema inspection first. Missing file -> NOT INITIALIZED, never create a fake funded account. Incompatible legacy schema -> UNSUPPORTED SCHEMA with no migration. Reject mixed/non-PAPER order modes; unknown legacy position metadata remains visible as unclassified, not silently stock/lot1/closeable. Snapshot timestamp is observation time, not quote time. Do not treat a copied ledger with unknown origin as confirmed broker evidence.

## Accounting basis
cash = sum(cash_ledger.delta_cash) - sum(cash_ledger.delta_fees). Initial allocation from existing funded metadata/initial_allocation cash event must reconcile, normally20000; never substitute20000 for missing evidence or treat a deposit as profit. This slice does not implement additional capital flows; unrecognized external cash events -> RECONCILIATION UNAVAILABLE rather than guessed P&L.

Active statuses match existing execution ledger (including UNKNOWN_SUBMISSION). Sum residual reserved_cash/risk only on active orders; terminal cancelled/filled remainders must be zero, inconsistent rows flagged. cash available = cash - active cash reserves (do not silently clamp negative); policy-limited strategy availability may be shown separately as min(available,20000), labeled allocation limit. Pending reduce-only SELL reserves units, not proceeds cash. Show owned/reserved-sell/sellable units with identity and whole-lot metadata; reject negative/inconsistent quantities.

Per open position q>0: cost basis=q*avg_price; stored mark value=q*mark_price only when mark finite positive; gross unrealized=q*(mark-avg); remaining paid entry fees=positions.entry_fees_inr; unrealized after paid entry fees=gross unrealized-remaining entry fees. This excludes future exit fees/slippage and is NOT net liquidation. Existing mark_price may be initialized from a fill; mark_time is not proof of a fresh broker quote. Show stored mark/time/age and provenance UNKNOWN or STORED LEDGER MARK, never BROKER LIVE. Missing mark -> unavailable valuation (do not COALESCE to avg and call it market value). If all marks usable, show cash+marked position value as STORED-MARK EQUITY, explicitly indicative/possibly stale. If any mark missing/invalid, portfolio equity/unrealized/total P&L unavailable; cash/realized facts remain visible.

Realized gross/net=sum(realized_events.gross_inr/net_inr); link fill_event_id to fills/orders/instrument for history. Realized net already subtracts allocated entry fee and exit fee. Fee totals paid=sum(fills.fees), reconcile to cash ledger fees; allocated realized fees=realized gross-realized net; remaining entry fees=sum(open entry_fees). Do not subtract total fees again from realized+unrealized net. Existing floats require deterministic Decimal(str(value)) read-side arithmetic and documented INR0.01 rounding/tolerance; do not rewrite source precision. A single explicit whole-book rounding tolerance (at most0.01) is acceptable with actual delta visible; do not loosen tolerances until errors pass.

When inputs/flows/marks reconcile: total P&L after paid fees=realized net+unrealized after remaining paid entry fees, which equals stored-mark equity-initial funding. Require cash from fills/funding, units from signed fills, fee allocation, realized-event identity and summary invariants to reconcile. Replay fill_event_id uniqueness; joins must not multiply fees/profits. Unknown legacy history -> reconciliation unavailable, not fabricated zero results. Never use this display's trust state to authorize orders or modify risk gates.

## UX
Dedicated Paper Account page using existing navigation conventions, no actions routed into Trade Ticket. Plain-language status and money labels; always LOCAL PAPER / STORED MARKS / NOT BROKER ACCOUNT. Show snapshot time and individual mark age. Put definitions next to gross/net values. Use separate cash/reserve facts, P&L facts and valuation limitations. A refresh button reads local DB only. No reset/fund/cancel/close/mark-edit/API buttons, automatic entries, or implied strategy approval. Missing/error states are readable and don't expose raw SQL/exception/path secrets.
