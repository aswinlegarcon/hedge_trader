# Design

## 1. Architecture and mode separation

Leave `ReadOnlyBroker` and existing GET clients intact. Add typed execution interfaces in a separate package: quote/instrument provider, account snapshot, validated candidate, preview authorization, execution adapter and reconciliation service. Mode enum PAPER / SANDBOX / LIVE is mandatory on orders, fills, accounts, positions and results; no default omission. App starts Paper. Switching mode invalidates pending previews and never replays an order.

Implement Paper locally for zero broker execution cost/dependency; data remains live Upstox where available. Sandbox is for payload/lifecycle integration only and must not be called an exchange-realistic paper performance service. Unsupported sandbox operations fail clearly and NEVER fall back to live hosts. LIVE uses an explicit production execution adapter, not a paper adapter with a renamed label.

Use distinct new local SQLite stores (or tables with strong account/mode constraints) for paper/live/sandbox execution. Default new stores may be data/paper_execution.db, data/live_execution.db, data/sandbox_execution.db, gitignored. Do not convert legacy `is_paper=1` journal rows into real trades or change user databases destructively. Legacy rows stay reference/unqualified; unknown actual broker exposure requires reconciliation. Initial funding event is idempotent. Mock tests use temp files.

## 2. Instruments, quotes and costs

Cash stocks/ETFs resolve current NSE identity from the existing master. NIFTY selector obtains actual tradable expiry/strike/CE-or-PE keys from current official contract/chain data; verify underlying, expiry, lot size, tick size and freeze limits. No hardcoded lot=65 or inferred holiday expiry for execution. Recheck metadata drift before submit. Integer stock units; NIFTY quantity must be a whole positive lot. No quantity scaling merely to fit a budget.

Use current two-sided quote/depth, not chart candles or LTP-only. Preserve source/evaluation timestamps, bid/ask/available quantity, tick units and instrument identity. Missing/crossed/nonfinite/future/stale inputs block new entries. Initial quote TTL 15 seconds, refreshed at Preview and again at Submit; this is an engineering default, not exchange-certified freshness. Distinguish source quote timestamp from last-trade time. A quiet last trade alone is not proof the quote is current or stale; if timestamp semantics cannot be established, block execution rather than inventing it.

Fetch current Upstox charges estimates and funding/margin requirements as appropriate for product/quantity, with source/time and a conservative exit-cost/slippage reserve. Broker fee-estimate API may not include every delivery/DP/exercise charge: expose coverage and require remaining date-effective inputs before qualified execution. Do not silently apply the old Zerodha options schedule as Upstox stock costs. Unverifiable fees/funding -> INSUFFICIENT DATA. Margin estimates are non-order POST requests and belong in an explicitly typed estimator, not generic order transport.

NIFTY buys risk full limit premium × quantity plus entry costs and conservative close/settlement-cost reserve; use applicable cash-settled NIFTY rules. No implied guarantee of a profitable exit or liquid market. If a minimum valid lot breaches ₹400, show 'no size fits policy'; no automatic cheap OTM strike selection. The analyst/user chooses a contract to inspect; no research score auto-selects trades.

## 3. Risk policy and shared gate

Create versioned execution-v1 policy with initial allocation 20,000, per-position budget 400, portfolio stop-new-risk drawdown threshold 2,000, interim aggregate risk cap 1,200, per-underlying 800 and count 3. One NIFTY underlying groups CE/PE exposure. No minimum risk and no automatic expansion on deposits/gains. Existing NSL legacy risk overrides do not silently change this policy; explicit named execution configuration replaces the old unconfirmed cap for this mode, while historical research fixtures can remain explicit.

Stock planned risk = (entry limit − selected protective stop reference) × units + conservative round-trip costs/slippage, requiring stop below entry for new longs. At-risk capital/full-to-zero downside is separately displayed, as is gap/stress loss; the stop does NOT guarantee ₹400 maximum loss. Do not apply full stock notional as if it were option premium-at-risk and thereby make every funded stock impossible; do not represent planned stock risk as contractual maximum. Proposed stop is a plan until broker protection is acknowledged. This first slice must disclose STOP NOT PLACED if no protective order is submitted; there is no implied automated stop. A user must explicitly acknowledge that state in the live preview. No unattended holding-management promise.

Option entry risk = premium-at-risk + required costs, independent of a premium stop reference. Known cost-inclusive risk must be ≤400. For total exposure report stock planned-risk sum plus option contractual-risk sum with clear mixed-basis label; full/gap stress exposure remains separate and never described as guaranteed drawdown containment.

Fix prior gate findings: context cannot understate candidate risk, NaN/inf or invalid/negative units/money cannot pass, profile identity and every limit validated, no fallback missing marks as zero, aggregate blocking reasons and reject-known-breach precedence, and no twice-checking the same stale object as a save-time refresh. Use integer paise/Decimal with explicit rounding. Stock and options share policy, funding/account checks, but retain different risk semantics.

Require current E/H/cash/positions/pending reservations and policy. Paper provider is its reconciled local ledger with fresh marks; live provider reconciles managed broker fills/orders/funds/positions with the local allocation ledger. D=max(0,H−E), initial_loss=max(0,C0−E); either at/above2,000 blocks new exposure. Pending orders reserve cash and risk so concurrent submits cannot overbook. Profits at risk cannot disappear from risk calculations. Cash/margin reserves affect available cash, never equity. Compare required funding to the lesser of broker-available funds and unreserved 20k strategy allocation. Existing unrelated broker positions/funds must not be automatically imported as strategy-owned; unresolved outside exposure/valuation blocks entry until explicitly reconciled, never auto-liquidated.

Unknown valuation/cost/funding/context -> INSUFFICIENT DATA, not a permanent production_context_blocked placeholder once real providers exist. Exit/reduce-only and cancel-working-order paths remain available despite an entry-risk breach, subject to exact ownership/quantity and fresh user confirmation. A loss ceiling blocks new risk; it is not a guarantee that gaps cannot exceed it.

## 4. Durable ledger and paper fills

Cash + signed market value of owned assets = equity. Premium/notional purchase is a cash reduction plus asset, not an immediate full realised loss; realise P&L only on sale/settlement, charge actual fees once. Persist initial allocation, fills, fees, positions, marked valuations/times and high-water mark across restart. Do not add realised P&L to cash twice. Unique event/trade IDs give idempotent replay. External flows need explicit flow adjustment; unsupported flows block entry rather than reset H.

Local paper marketable LIMIT buy may fill at current ask plus explicit slippage only up to the user's limit, sell-to-close at bid minus slippage within limit; never fill from stale candles/price midpoint by default. Cap fill quantity to visible available depth, reserve remainder as working; unknown size means no automatic fill. Non-marketable limit stays pending until an explicit fresh evaluation, never retroactively fills from a candle high/low. Simulated fill model and timestamp recorded; settlement uses verified final values or stays unresolved. Paper mode never calls broker order endpoints.

## 5. Order ticket, submission and live readiness

Trade Ticket preview freezes mode/account/key/expiry/side/units/price/product/fees/funding/risk/stop-plan and exposes quote/as-of and policy. Visible Paper vs LIVE money banner. Confirm button is instrument-specific e.g. 'Submit LIVE BUY [quantity] [symbol] at limit [price]'; no generic hidden submit on mode change/rerun. User confirmation is single-use, short-lived (30s), bound to exact ticket identity. Any changed inputs require new preview. Just before submission refresh quote/account/fee context; materially changed numbers invalidate preview and require user review, never silently rescale/reprice.

Persist a local request ID and reservation before sending. Disable double-click/repeated reruns server-side with an atomic unique constraint. Broker tag is tracking aid, not proof of broker idempotency. No automatic retry of place/modify/cancel POST/PUT/DELETE on timeout/5xx. If send outcome is unknown, mark UNKNOWN_SUBMISSION, keep reservations, reconcile orderbook/history/trades by returned ID/tag/time, and block another conflicting intent. Do not mark timeout as rejected and blindly resubmit.

Poll status only under bounded explicit refresh or a narrowly bounded post-submit reconciliation. Accepted order ID != filled. Handle PENDING, OPEN, PARTIALLY_FILLED, FILLED, REJECTED, CANCEL_REQUESTED, CANCELLED, UNKNOWN_SUBMISSION with broker-state mapping. Unique broker trade IDs book fills exactly once; cancelled remainder releases reservations, filled part remains. Restart restores unresolved orders before new submission. Close ticket cannot sell more than reconciled owned quantity minus pending sells.

Provide user-confirmed cancel/reduce-only close actions for app-owned orders/positions, plus local Stop new orders; stopping local submissions does not imply existing broker orders are cancelled or positions flattened. No automated exit-all. Broker-side protective stops and multi-leg execution need a follow-on contract; do not label them working when absent.

Live readiness: local order-capable access token, current broker quote/account/cost data, reconciled ledger, fresh instrument permissions/market session and applicable static-IP/app requirements. Read registered static IP only if needed; do not change IP/app permissions or tokens. Current endpoint docs determine Algo-Name applicability; no invented compulsory Algo ID for every manual order. Refuse new placement outside the supported regular session; market-data-hours assumptions are insufficient, and broker may infer AMO regardless of payload.

Both Paper and Live are selectable implemented workflows. Account-specific readiness failure shows exact setup/data blocker; do not call it a policy ban. Default Paper and no automated strategy engine; enabling Live in UI is not confirmation of an order. User performs live financial confirmation; agents must not use the UI or direct requests to test a live order.

## 6. Transport and credentials

Separate Paper engine (no order HTTP), Sandbox adapter (separate backend UPSTOX_SANDBOX_ACCESS_TOKEN) and Live adapter (existing backend token). Pin each environment to verified official hosts/paths; verify sandbox V3 path from current official source before coding, never guess by replacing a hostname. Do not use a sandbox-unavailable call as an excuse to send live. Production V3 order host documented as api-hft.upstox.com; status/read-only API host api.upstox.com. Keep broker data transport GET-only and order adapter explicit; no arbitrary host override in UI.

Never log/display credentials, raw headers, sensitive account payloads or `.env`. Paper/live stores and account information are local private data, gitignored; no capture into handoff. Runtime may privately request required funds/positions/orders under this implementation scope, but agents' automated tests use fakes and live accounts are not dumped. Do not add payment/payout endpoints.

## 7. Verification and rollout

Implement in dependency order: mode/types/ledger and risk repairs; quotes/contracts/funding/cost providers; paper lifecycle; sandbox mapping; actual live adapter and preview/reconcile UI. This is one execution feature with dependent tasks, not permission for unrelated refactors. Complete code paths without stopping after a live-disabled skeleton. If broker access unavailable, finish mocks/paper and report account-specific setup blocker honestly.

Automated suite must forbid real live mutations. Cover stock and NIFTY Paper+Live adapter contracts via mocked transport, host/token separation, mode-switch invalidation, preview/recheck changes, finite money/profile validation, old ₹4,797.82 understated-as-zero/NaN gate reproductions, cash/ledger/fees/peak math, whole-lot policy, missing/static-IP/access failures, duplicated UI submit, partial fill/cancel/restart and UNKNOWN_SUBMISSION recovery. Meaningful UI integration through Preview→Confirm with fake broker, not just module function tests. Include live side effects negative test during app load/research refresh.

Optional sandbox order lifecycle smoke only if separate sandbox token exists; clearly mark sandbox, persist test IDs separately and never fall back. Real read-only quote/contract/account readiness may be checked privately with sanitized counts/status. No live place/modify/cancel/close test by implementation agent. User submits the first real order only after reviewing actual ticket. Handoff says 'implemented; live adapter mocked; real live placement not tested' when that is the evidence. Paper/sandbox returns are not investment performance or proof of predictive accuracy.
